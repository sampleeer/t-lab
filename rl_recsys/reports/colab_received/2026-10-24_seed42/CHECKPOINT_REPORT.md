Протокол прежний: полный обученный каталог, OOV-цели остаются промахами,
rolling реальные истории, усреднение сначала внутри пользователя. Test:
4000 событий, 906 пользователей. Сравниваются модели одного seed; исходное
среднее двух seed из основного отчёта сюда не подставляется.

Парный bootstrap пользователей на test, 2000 повторов:
ΔNDCG=0.007210, 95%-интервал
[0.003183; 0.011518].
ΔRecall=0.015148, 95%-интервал
[0.008810; 0.022203].
В обоих случаях интервал выше нуля на этом фиксированном срезе.

Это ранее использованный test-период. Проверка описательная/разведочная,
а не новый независимый holdout после разработки. Bootstrap не учитывает
выбор checkpoint, неопределённость обучения и перенос на другой период.
Рост нельзя приписать только числу эпох: одновременно увеличена train-выборка.

## Поведение

Охват каталога top-10 вырос с 63.09% до
89.62%. Доля самого частого top-1 —
11.03% и 10.65%: глобальной
концентрации, наблюдавшейся у слабого RL, здесь не видно.

Доля top-1, встречавшегося в последних 24 реальных событиях, выросла с
24.92% до 50.30%.
В музыке повтор может быть релевантным, но при следующих экспериментах
полезно отдельно оценивать повторные и новые треки.

Старая RM прогнозирует среднюю долю 0.657480 и
0.656098. Улучшение ranking не сопровождается ростом этого
proxy. RM и аудитор не дообучались; их прежние ограничения сохраняются.
Не следует считать эти прогнозы наблюдаемой наградой или эффектом на retention.

## Подтверждение по полному Colab-архиву

Дополнительно получен `yambda_continue_v1_seed42-20261023T220859Z-1-001.zip`.
Все девять файлов сохранены в отдельной папке `colab_export` рядом с весами.
Архив содержит точные train/validation/test-контексты, каталог, конфигурацию,
историю, runtime metadata и полный checkpoint. Проверки — `colab_export_checks.json`.

- `best.pt` побайтово совпадает с отдельно полученными весами.
- `temp.pt`: эпоха 20 завершена, global_step=39080, best_epoch=16.
- Лучшие веса внутри temp.pt совпадают с best.pt, история — с history.json.
- SHA256 train/validation/catalog/config совпадают с записанными в run.json.
- Начальные веса и код runner совпадают с локальными исходниками.
- Test совпадает побайтово; все массивы восстановленного validation тоже
  совпадают точно с исходными. Различается только упаковка validation.npz.

catalog.npz нужны для воспроизведения; temp.pt — для возобновления обучения.
