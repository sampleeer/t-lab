# Протокол до расчёта результатов

Источник: Yambda, flat/50m/listens.parquet, закреплённая ревизия и SHA256.
Детерминированная выборка пользователей по хешу ID (примерно 10%). Сохраняются
все их события. Глобальные границы train/validation/test — 70-й и 85-й
перцентили времени. Timestamp Yambda — секунды с точностью пять секунд
(формула раздела 3.3 статьи о Yambda); календарные даты
не восстанавливаем. Каталог — 4096 наиболее частых треков строго из train.
Остальные события сохраняются в контекстах как UNK; OOV-цели учитываются
как промахи при основной оценке. Повторные рекомендации разрешены всем методам.

Контекст: последние 24 события со временем строго меньше целевого. Минимум
три предшествующих события. Validation/test — случайно до восьми событий
пользователя, до 4000 суммарно; метрики усредняются сначала по пользователю.
Внутри holdout разрешены более ранние реальные события: rolling evaluation.
Для прокси продолжения исключается последний 30-минутный интервал каждого
среза. Веса моделей не обновляются на validation/test.

Базовая модель — GPT2Model, 2 слоя × 64, 4 головы, обучение с нуля на item ID.
Next-item cross entropy, полный обучающий каталог, до 80000 случайных train
контекстов, пять эпох; эпоха выбирается по validation NDCG@10. Сравнение с
популярностью и последним объектом + популярность. Два seed: 42 и 2026.

Reward model обучается на до 160000 train-событий: история ID, два выхода:
clip(played_ratio_pct/100,0,1) и наличие следующего зарегистрированного
прослушивания в пределах 30 минут. Последнее — ассоциация, не причинный
эффект рекомендации и не возвращение на следующий день. Выбор эпохи по
validation MSE доли + Brier продолжения. Контрольные модели: train mean,
сглаженные item means; независимая RM с другим seed и отдельной случайной
подвыборкой train используется как диагностический аудитор. RM не видит
реакцию на оцениваемый объект во входных признаках.

RL: on-policy REINFORCE внутри замороженной RM, полный каталог. Для каждого
состояния вычисляется точный baseline E_pi[R]; score-function gradient для
сэмплированного действия и точный KL(pi||pi_SFT). Одно обновление на rollout,
без importance weights: это не off-policy RL на реальных пользователях.
При горизонте 5 применяются discounted returns (gamma=0.95), вычитается
точный однокроковый baseline; он зависит только от состояния и не смещает
градиент. Переход добавляет рекомендацию в контекст как будто она принята.
Это предположение симулятора, проверяемое диагностикой frozen context.

Варианты: доля с beta=0.01 и 0.2; ожидаемое время (доля × train median
duration, cap 600 s, /300) с beta=0.2; смесь 0.5 доли + 0.25 времени +
0.25 продолжения, horizon=5, beta=0.2. Каждый стартует от одного SFT-checkpoint.
Все 300 обновлений сохраняются через 100 шагов. По validation выбирается
максимальная одношаговая E_pi[R] на реальных историях при NDCG@10 >= 95% SFT
(также для H=5 это одношаговый критерий отбора, не полная оценка return); если ограничение
невыполнимо, используется исходный checkpoint (нулевое обновление).
Последняя итерация сохраняется и оценивается отдельно как stress endpoint.
Варианты сравниваются отдельно; победитель по test не выбирается.

Метрики: Recall/NDCG/MRR@10, модельная доля и время, аудиторская оценка,
KL, энтропия, охват каталога, доля наиболее частого top-1, overlap списков,
повтор в последних 24 событиях, train-популярность, длительность. Оценка
пяти шагов: прирост RM, повторы, KL, сравнение с frozen context; оценка
правдоподобия истории исходной SFT. Парный bootstrap по пользователям,
2000 повторов, отдельно на каждом seed; seed не независимые выборки данных.

Тестовые ответы не участвуют в выборе эпох, коэффициентов, checkpoint и каталога.
Модельное вознаграждение вне logged support не является наблюдаемой наградой.
Без вероятностей показов нет достоверного IPS/DR и доказательства retention.
