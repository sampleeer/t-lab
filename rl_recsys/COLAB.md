# Продолжение обучения в Colab

Ноутбук: [COLAB.ipynb](COLAB.ipynb).
Загрузите его через File → Upload notebook на https://colab.research.google.com/.
Выберите GPU в настройках среды выполнения и выполняйте ячейки сверху вниз.
По запросу загрузите `deliverables/rl_recsys_colab.zip` и подключите Google Drive.

Что делает ноутбук:

- Загружает текущие SFT-веса; новый запуск не начинается со случайной модели.
- Расширяет train до 500000 SFT-целей и 600000 подготовленных целей RM.
- Сохраняет исходные каталог, validation и test. Test не используется в обучении.
- Выполняет до 20 дополнительных эпох SFT на GPU; validation считает на CPU.
- При RUN_REWARD=True отдельно продолжает RM с меньшим learning rate.
- Выбирает лучшие веса по validation, включая исходную модель как эпоху 0.
- Сохраняет полные checkpoints и подготовленные входы в Drive.
- Сохраняет `best.pt` с лучшими весами по validation и `temp.pt` для продолжения.
- Обновляет `temp.pt` каждые 100 батчей и в конце каждой эпохи.
- Возобновляет запуск с сохранённой позиции внутри эпохи при повторном выполнении.
- Предлагает скачать `rl_colab_results.zip` с весами, состоянием, кривыми и входами.

При первом продолжении AdamW создаётся заново: в исходном исследовании сохранены
веса без optimizer state. Дальнейшие restart восстанавливают optimizer и RNG.
В `temp.pt` входят текущие веса, optimizer state, RNG, порядок train-примеров,
позиция следующего батча, номер эпохи, счётчик шагов и лучшие веса.
`best.pt` обновляется после validation только при улучшении метрики: NDCG@10
для SFT и joint MSE/Brier для RM. Исходная модель участвует как эпоха 0.
После обрыва повторяются только батчи после последнего успешного сохранения.
Частота задаётся `SAVE_EVERY_BATCHES` в ноутбуке или `--save-every-batches` в CLI.
Оба файла записываются через временный файл с заменой после завершения записи.
Старые epoch-checkpoints `last.pt` поддерживаются: при первом возобновлении
они переносятся в формат `temp.pt` без изменения данных и параметров обучения.
Чтобы изменить LR, batch size или данные, используйте новый RUN_NAME.

Файлы сохраняются отдельно для моделей:

```text
MyDrive/rl_recsys_runs/<RUN_NAME>/sft_seed42/best.pt
MyDrive/rl_recsys_runs/<RUN_NAME>/sft_seed42/temp.pt
MyDrive/rl_recsys_runs/<RUN_NAME>/reward_seed42/best.pt
MyDrive/rl_recsys_runs/<RUN_NAME>/reward_seed42/temp.pt
```

Загрузка только весов вручную:

```python
model.load_state_dict(torch.load("best.pt", map_location="cpu", weights_only=True))
# temp.pt — полный checkpoint, его веса находятся под ключом model.
checkpoint = torch.load("temp.pt", map_location="cpu", weights_only=False)
model.load_state_dict(checkpoint["model"])
```

Для восстановления также optimizer/RNG/позиции батча повторите запуск ноутбука
с теми же настройками и RUN_NAME. Используйте обновлённый Colab-архив;
если старая копия уже была загружена в сессию, ноутбук запросит новую.

Ограничения:

- Текущая архитектура и словарь из 4096 треков сохраняются. Для расширения
  каталога требуется отдельный эксперимент с новым mapping/выходным слоем.
- Дообучение существующей RM не гарантирует усиления персонализации.
- Новый RL автоматически не запускается. Сначала нужно оценить новые SFT/RM
  на validation, затем провести отдельное контролируемое RL-сравнение.
- Старый test уже использовался в анализе; новое улучшение следует подтверждать
  на новом временном holdout. Исходный REPORT описывает прежний запуск.
- CPU-паритет адаптации и точное возобновление проверены для SFT и RM.
  Локальная машина CPU; переданный реальный Colab-прогон на Tesla T4 проверен,
  лучшие веса — эпоха 16/20. Итоги: [FINAL_REPORT.md](FINAL_REPORT.md).
- GPU и длительность сессии Colab зависят от доступных ресурсов:
  https://research.google.com/colaboratory/faq.html .

Исходные код обучения, веса и `rl_recsys_complete.zip` сохранены без изменений.
Новый `rl_recsys_colab.zip` содержит исходный архив и дополнительные Colab-файлы
в одной структуре `rl_recsys/`. Установка сохраняет PyTorch с CUDA из Colab;
локальный `requirements.txt` для CPU-эксперимента не применяется автоматически.

После проверки Colab выполнен отдельный RL-эксперимент с новой feedback-aware RM.
Его воспроизведение описано в [FINAL_REPORT.md](FINAL_REPORT.md). Сам этот ноутбук
продолжает исходные SFT/RM. Ячейка загрузки ищет ZIP в
`/content/drive/MyDrive/rl_recsys_colab.zip`; validation включена в обновлённый
архив, а для старого ZIP реализовано восстановление исходных splits.
