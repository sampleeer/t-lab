# KION: ручные признаки и автоматический отбор агрегатов

Исследовательское задание выполнено: ручной baseline, генерация 144 признаков,
автоматический отбор, абляции и анализ. Основная версия усилена проверкой
на трёх тестовых неделях и двух seed, подбором baseline по NDCG и временными
out-of-fold ошибками для отбора. Начните с [итогового отчёта](REPORT.md).
Первоначальный опыт на одной неделе сохранён в [PILOT_REPORT.md](PILOT_REPORT.md).

## Воспроизведение

Python 3.10. Команды выполняются из корня проекта. CPU, GPU не требуется.
Основной запуск: 50 000 пользователей для статистик, 3 000 случайных
warm-пользователей на каждую обучающую неделю, до 200 кандидатов на пользователя.
В усиленной версии train-пары сэмплируются с importance weights: все positives
и до 30 negatives на пользователя. Истории остаются полными; validation/test
используют полный список кандидатов.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.download
python -m unittest discover -s tests -v
python -m src.pipeline prepare
python -m src.pipeline fit
python -m src.pipeline evaluate
python -m src.diagnostics
python -m src.auto_pipeline prepare
python -m src.auto_pipeline fit
python -m src.auto_pipeline evaluate
python -m src.robustness prepare
python -m src.robustness fit
python -m src.robustness evaluate
python -m src.final_report
```

После загрузки данных и проверок `python -m src.pipeline all` выполняет baseline,
а `python -m src.auto_pipeline all` — исследовательский этап. Если baseline
уже подготовлен, повторять его не нужно. `src.final_report` заново собирает
отчёт и компактные таблицы по сохранённым результатам этого исследования.
Для первого скачивания нужен интернет. Используется полный официальный архив
из закреплённого коммита, проверяется ZIP CRC. Контрольные суммы конкретного
использованного источника сохраняются в `data/raw/manifest.json`.

Все параметры — в [config.json](config.json). Для другого эксперимента создайте
отдельный JSON и отдельную выходную папку:

```bash
python -m src.pipeline all --config my_config.json --output artifacts/my_run
```

Пример меньшего прогона: `sample_users=10000`,
`train_users_per_snapshot=2000`; менять число кандидатов и даты между моделями
одного сравнения нельзя. Смена параметров требует повторить `prepare` и `fit`.
Результаты не гарантируют идентичности последних битов на разных платформах.

Параметры генерации/отбора — в [auto_config.json](auto_config.json).
Для другого baseline используйте `--baseline artifacts/my_run` и отдельный
`--output` у `src.auto_pipeline`. При изменении опыта потребуется обновить
интерпретацию отчёта; шаблон `src.final_report` описывает выполненное исследование.

Усиленная проверка: [robust_config.json](robust_config.json). Если baseline
уже подготовлен, достаточно `python -m src.robustness all`, затем
`python -m src.final_report`. Новый fit возобновляется по завершённым моделям;
при изменении конфигурации используйте отдельный `--output`. Тестовые метрики
новой версии рассчитываются после фиксации всех трёх fold-настроек.

## Содержимое артефактов

`artifacts/baseline/` (не включается в Git):

- `sample_users.csv`, `sample_events.parquet` — выбранные пользователи и все
  их доступные строки; события не сэмплируются.
- `manifest.json` — даты, численности, версии, SHA256, конфигурация и время.
- `train_*.parquet`, `validation.parquet`, `test.parquet` — фиксированные
  кандидаты, признаки и метки. В файлах truth — полные ответы для метрик.
- `selection.json` — конфигурация, выбранная по validation NDCG@10.
- `model_*.cbm`, `ablation.cbm`, `importance_*.csv` — модели и важности.
- `results.json`, `test_metrics.csv`, `test_users_*.csv`,
  `test_predictions.parquet` — итоговая оценка, интервалы и предсказания.

`artifacts/auto_features/`:

- `train_*_*.parquet`, `validation_*.parquet`, `test_*.parquet` — блоки
  автопризнаков в том же порядке, что baseline; test считается после выбора.
- `catalog.json`, `screening.csv`, `screening.json` — грамматика и отбор.
- `selection.json`, `*.cbm`, `importance_*.csv` — выбор по validation,
  четыре обученные модели и важности признаков.
- `results.json`, `test_users_*.csv`, `test_predictions.parquet` — тест,
  доверительные интервалы и парные сравнения.

Компактные копии результатов хранятся в `reports/auto/` и входят в архив кода.
В исходный код и архив не включены большие данные/кэши и веса моделей:
они воспроизводятся командами выше. Все локально обученные веса сохранены
в `artifacts/`. Протокол второго этапа прямо учитывает, что test baseline
был открыт раньше; полностью слепая внешняя проверка не заявляется.

`artifacts/robustness/`: общие взвешенные train-наборы и полные eval-наборы
в `data/`; в `fold_*/` — поиск depth/trees, временные prefix-модели, OOF scores,
четыре метода для двух seed, per-user метрики и предсказания. Настройки всех
folds — `selection.json`; результаты — `all_results.csv`, `weekly_results.csv`,
`paired_intervals.csv`, `results.json`. Компактные копии — `reports/robust/`.

Для повторной оценки готовых моделей достаточно `evaluate`. При этом
модели не переобучаются. Тест нельзя использовать для последующих решений
о признаках/параметрах в рамках этого же эксперимента.

Посмотреть названия рекомендованных фильмов для конкретного пользователя:

```bash
python -m src.recommend --user-id USER_ID --save recommendations.csv
```

Замените `USER_ID` числом из `artifacts/baseline/sample_users.csv`. Нужен
пользователь с историей на начало теста; по умолчанию используется именно
этот срез. `--cutoff YYYY-MM-DD` позволяет явно задать другую дату.
Этот просмотр использует замороженную модель и не требует целевых меток.
Команда `recommend` относится к исходному pilot-baseline; новые модели
сохранены отдельно в `artifacts/robustness/fold_*/`.
`src.diagnostics` после тестовой оценки создаёт `reports/history_segments.csv`
и три случайных примера с названиями фильмов в `reports/03_examples.md`.

## Как устроены данные и целевая переменная

Каждая строка KION — пара user–item, `last_watch_dt`, суммарная длительность,
доля просмотра. Это агрегат, **не полный поток событий**. На срезе t используем
строки с `last_watch_dt < t`. Предсказываем наличие строки для пары в
следующие 7 дней. Пары из истории исключаем. Для горизонта модель оценивает
`P(строка в следующую неделю | сформированные кандидаты, признаки)`.

Из такого агрегата нельзя восстановить полную реальную историю на t: пара
с последним просмотром после t могла иметь более ранние просмотры. Поэтому
это proxy-задача, а не точная оценка новых просмотров/CTR. `total_dur` и
`watched_pct` берём только у строк, последний просмотр которых уже в прошлом.
Положительный ответ — любая запись; минимальную длительность не подбираем.

В учебном задании требуется сохранять историю пользователей при сэмплировании:
мы сохраняем все доступные строки, но не утверждаем, что источник содержит
каждое отдельное действие. Метаданные считаем постоянными, исторических версий
нет. Фильмы доступны генератору только после первого наблюдения в истории.

## Ручные признаки и кандидаты

Генератор объединяет популярные фильмы, недавние популярные, популярные
в любимых жанрах и соседей по совместным просмотрам. Последние — косинус
между бинарными векторами пользователей для фильмов, по 50 соседей на фильм;
вклад истории пользователя затухает с масштабом 30 дней. Источники объединяются
Reciprocal Rank Fusion с константой 60; оставляем до 200 фильмов, исключая
наблюдавшиеся пары. Ни одного ответа из будущего не добавляем искусственно.

Ручные признаки:

- Для пользователя и фильма: число строк, средние `watched_pct` и `total_dur`
  за 7/30 дней и всё прошлое, давность последней строки, время от первой,
  отношение недельного числа строк к общему (с +1 в знаменателе).
- Для пары: жанровые, страновые, режиссёрские и актёрские предпочтения за
  всё прошлое и 7 дней; сумма частот общих категорий, нормированная на число
  категорий фильма и размер истории пользователя. Косинусный item-item score,
  RRF и место в списке генератора.
- Демография пользователя; тип, возрастной рейтинг, детский флаг, год выпуска,
  жанры, страны и режиссёры фильма. Пропуски категорий — `unknown`, чисел — 0.

ID пользователя и фильма в модель не подаются. Частотные отношения признаков
сглажены. Ручные признаки не используют target encoding. Внутренние
категориальные статистики CatBoost обучаются на train; метки validation
используются для ранней остановки и выбора конфигурации. Нет случайного
разбиения событий, искусственно добавленных целевых фильмов или исключения
из кандидатов фильмов по будущему просмотру.

В исходном пилоте CatBoostClassifier обучается на всех кандидатах случайных warm-пользователей,
без балансировки классов и без отрицательного сэмплирования по меткам.
Остановка по validation LogLoss (patience 60), выбор из двух глубин по
validation NDCG@10. На тесте веса заморожены; история признаков обновляется
по всем строкам, которые к тестовому срезу стали прошлым.

В усиленной версии применяются одинаковые взвешенные train-пары для всех
методов; depth/trees выбираются непосредственно по validation NDCG@10.
Для автоотбора используются только прогнозы временных prefix-моделей на
следующей train-неделе, затем отобранные признаки входят в обучение на всех
трёх неделях. Алгоритм и ограничения — в текущем REPORT и протоколе усиления.

## Оценка

Основные метрики — средние по warm-пользователям с хотя бы одним целевым
фильмом: NDCG@10 и Recall@10. Недоступные фильмы и промахи генератора
**остаются в знаменателях**. Дополнительно: полнота кандидатов, верхняя граница
NDCG@10 внутри кандидатов, число холодных пользователей/фильмов. AUC/LogLoss
относятся только к парам из генератора и не являются оценкой CTR.

Контроли: популярность за всё прошлое, за 7 дней, RRF и item-item score.
Абляция: бустинг без признаков связи пары и ранга генератора, с теми же
кандидатами. Генератор всё ещё персонализирован: абляция измеряет вклад
персональных признаков ранжирования, а не отключение всей персонализации.
95%-интервалы — bootstrap пользователей; прирост дополнительно оценивается
парным bootstrap относительно контроля, выбранного на validation.
Они не учитывают вариативность выбора 50 000 пользователей и недель.

Автоматический метод, его абляции и ограничения описаны в [REPORT.md](REPORT.md).
Подбор новых параметров по итоговым test-метрикам не проводился. В репозитории
сохранены все результаты, включая отрицательный пилот. Средние новой версии
описывают три недели; шесть запусков не считаются независимыми. Интервалы
bootstrap считаются внутри каждой недели, для общего среднего CI не заявляется.
